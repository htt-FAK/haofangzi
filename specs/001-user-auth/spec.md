# SPEC 001 · 用户注册登录与购房画像

**版本**: v1.0 | **状态**: Approved | **依赖**: `specs/000-program/spec.md`
**报告落点**: `docs/02-需求分析` §2.1、`docs/03-概要设计` §3（用户服务模块）、`docs/05-用户手册` §2

## 1. 目标（WHY）
没有账号体系就无法沉淀偏好、无法记录选房意向、无法管理预约归属。本域为全系统提供身份、
权限边界与画像数据（004 的个性化权重、007 的顾问输入均依赖它）。

## 2. 用户故事

| 编号 | 作为… | 我想要… | 以便… |
| --- | --- | --- | --- |
| US-01 | 购房者 | 用手机号 + 验证码/口令注册并登录 | 无需第三方即可开始选房 |
| US-02 | 购房者 | 首次登录后完成 4 步画像（预算、家庭结构、必需居室、偏好标签） | 系统能给出贴合的方案 |
| US-03 | 购房者 | 随时修改画像 | 需求变化后推荐随之更新 |
| US-04 | 销售顾问 | 用顾问账号登录并查看绑定客户的画像与意向 | 提前准备带看方案 |
| US-05 | 管理员 | 停用违规账号、重置口令 | 平台治理 |
| US-06 | 购房者 | 注销账号（数据匿名化） | 行使隐私权利（NFR-13） |

## 4. 验收标准（AC，Given/When/Then）

- **AC-01** Given 已注册手机号，When 用错误口令连续登录 5 次，Then 第 6 次返回 `40305` 且提示剩余锁定秒数，锁定 900s。
- **AC-02** Given 新用户注册成功，When 未填画像，Then 画像完整度为 0%，首页显示"完善画像"引导，智能顾问入口置灰并提示原因。
- **AC-03** Given 画像预算 120~160 万、最少 3 房，When 保存，Then 户型列表默认带上该筛选条件，且再次进入页面仍保持。
- **AC-04** Given `BUYER` 令牌，When 调用 `PUT /api/admin/users/{id}/status`，Then `40302` 且审计日志记录本次越权尝试。
- **AC-05** Given 用户注销，When 查询其收藏/评测记录，Then 记录仍在但 `nickname` 为匿名值、`phone` 为空，导出报告中不含手机号。
- **AC-06** Given 令牌过期，When 调用任意需登录接口，Then `40101`，前端跳登录页并保留回跳地址。
- **AC-07** Given 口令以 `Abc12345` 入库，When 直接查库，Then 数据库中存在的是不可逆散列（前缀 `$2a$`，cost≥10）。

## 5. 范围外
微信/支付宝授权登录（本期只留 `openid` 字段占位）、实名人脸核验、图形验证码的商业 SDK、多端 SSO。

## 6. 界面与交互要点
`/login`（口令 / 验证码双 Tab）、`/register`（手机号 + 图形码 + 口令强度条）、`/profile/wizard`（4 步分步表单）、
`/admin/users`（表格 + 停用/重置操作）。空态：无可视化时显示占位插画与"去完善画像"。

## 7. 依赖与被依赖
依赖：`sys_user` 表、短信/验证码服务（演示环境用固定码 `123456` + Mock 实现）。
被依赖：003（锁房需 `user_id`）、004（个性化权重）、005（报告归属与分享）、006（预约人身份）、007（顾问画像输入）。
