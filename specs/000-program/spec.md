# SPEC 000-PROGRAM · 全局规格：范围、非功能需求与验收总则

**版本**: v1.0 | **状态**: Approved | **所属**: `constitution.md` v1.0.0 之下
**报告落点**: `docs/01-可行性分析` §2 系统目标、`docs/02-需求分析` §1 引言 + §4 非功能需求

## 1. 项目背景（WHY）

肇庆市推进"好房子"建设（安全、舒适、绿色、智慧），购房者面对多楼盘、多户型、多楼层信息分散，
缺少**客观、可解释、可对比**的选房工具；楼盘销售端则存在客源意向不清、看房预约线下登记低效的问题。

本系统提供：户型 2D/3D 在线展示 → 条件筛选与模拟选房 → 规则化智能评估打分 → 多方案对比报告 →
线下看房预约闭环，并在评估规则、对比结论、选型建议、3D 建模代码四个环节引入大模型生成能力。

## 2. 干系人与角色

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| 购房者 BUYER | 注册用户，选房主体 | 少跑腿、看得懂、比得清、选得准 |
| 销售顾问 CONSULTANT | 楼盘方 | 管理预约、了解客户偏好、跟进线索 |
| 系统管理员 ADMIN | 项目组/平台方 | 维护楼盘户型数据、评估规则集、报表 |
| 指导老师 Supervisor | 课程验收 | 检查文档规范、方法工具运用、分工与可运行性 |

## 3. 范围（SCOPE）

**In**：肇庆市 3 个"好房子"示范楼盘、20 个户型、约 600 套房源的展示与评估；规则打分与可解释输出；
对比报告（导出 PDF/分享链接）；预约看房与站内提醒；AI 四项创新能力（可降级）。
**Out**：见宪法第三条（真实支付、网签、实名核验、贷款测算、数据抓取、自建渲染引擎）。

## 4. 非功能需求（NFR，全局唯一编号，各域 spec 引用而非重复）

| 编号 | 类别 | 指标（可测） | 验证方式 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 户型列表 p95 ≤ 500ms；单房源评分 ≤ 200ms（不含 LLM） | JMeter 50 并发 / 100 次采样 |
| NFR-02 | 性能 | 3D 场景首屏可交互 ≤ 3s（≥ 10Mbps 内网） | Lighthouse + 手工计时 |
| NFR-03 | 可用性 | 新用户 3 分钟内走通"筛选→户型→评分"主路径 | 5 名非组员可用性测试 |
| NFR-04 | 可靠性 | 服务可用率 ≥ 99%（演示期内）；LLM 不可用时功能降级不报错 | 故障注入 |
| NFR-05 | 并发 | 同一房源 20 人并发"选房"，仅 1 人成功锁定，无脏写 | 并发用例 TC-P-01 |
| NFR-06 | 安全 | 口令 BCrypt(cost≥10)；写接口 100% 鉴权；PII 日志/导出脱敏 | 代码评审 + TC-S-01~05 |
| NFR-07 | 安全 | 分享 token 随机 ≥ 128bit、只读、默认 7 天过期 | TC-S-06 |
| NFR-08 | 可维护 | 改评分规则**不需改代码**（JSON 外置 + 热加载）；包结构与概要设计 1:1 | 变更演练 |
| NFR-09 | 可观测 | 统一响应体、traceId、错误码表；关键操作审计留痕 | 抽查 |
| NFR-10 | 兼容性 | Chrome/Edge 最新两版 ≥ 1280px；移动端 H5 只读页面可用 | 手工矩阵测试 |
| NFR-11 | 可解释 | 每条评分须给出"指标值 + 命中分档 + 依据规范条文" | 评分明细页 |
| NFR-12 | 数据 | 所有表含 `id/created_at/updated_at/deleted`；金额 2 位小数、面积 2 位小数 | schema 校验 |
| NFR-13 | 隐私 | 用户画像数据仅本人和授权顾问可见；提供数据删除（软删 + 匿名化） | TC-S-07 |
| NFR-14 | 文档 | 每个功能域 ≥ 1 图 + 1 可运行入口；DFD 至少画到 1 层 | 组长巡检 |

## 5. 全局验收总则（每域 spec 的 AC 必须与之不冲突）

- **Given/When/Then** 书写，必须可被一条测试用例（`docs/06-测试计划` TC-xxx）覆盖。
- 任一功能点的交付需同时满足：契约通过、接口联通、前端有入口、文档有落点。
- 需求变更走 MR：改 `spec.md` → 更新编号版本 → 回归受影响用例 → `docs/` 同步。

## 6. 设计约束与被排除方案（答辩常被追问，先记录）

| 议题 | 决策 | 理由 |
| --- | --- | --- |
| 结构化 vs 面向对象方法 | **两者并用**：需求阶段用 DFD/数据字典（结构化），设计阶段用用例图/类图/状态图（OO） | 课程要求"运用系统流程图、DFD、数据字典，若 OO 则用例图/类图/状态图" |
| 单体 vs 微服务 | 单体分域 | 3-4 人 6 周，部署与答辩成本最低 |
| 评分是否用机器学习模型 | **规则打分为主 + ML/AI 为辅**（AI 只生成规则与解读，不直接给分） | 保证可解释性与成绩可信度，符合 NFR-11 |
| 是否自建 CAD 解析 | 否，人工录入参数 + 手绘 SVG | 超出课程范围，数据可控 |
