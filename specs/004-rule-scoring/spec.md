# SPEC 004 · 户型规则打分与可解释评估（创新点 I1 主战场）

**版本**: v1.0 | **状态**: Approved | **对应题目**: 核心模块 3「规则打分模块」
**报告落点**: `docs/02-需求分析` §2.4、`docs/03-概要设计` §3.4、`docs/04-详细设计` §4（算法 + 判定表）、`docs/06` TC-E-xx

## 1. 目标（WHY）
销售话术里"南北通透、采光极佳"无法验证。本域把这些说法落成**可计算指标 + 分档打分 + 证据链**，
让每个总分都能回答三件事：分怎么来的？差在哪一条？改了能涨几分？
评估结果同时是 005 对比报告与 007 顾问推荐的唯一事实来源。

## 2. 评分维度（7 维 100 分，默认权重）

| 维度 code | 名称 | 权重 | 考察点（示例指标，共 21 个） |
| --- | --- | --- | --- |
| LIGHT | 采光与日照 | 22% | `LIGHT_wfa` 客厅窗地比、`LIGHT_orientation` 主朝向、`LIGHT_bay_depth` 面宽进深比、`LIGHT_floor_occlusion` 低层遮挡衰减、`LIGHT_dark_bath` 暗卫 |
| VENT | 通风与对流 | 18% | `VENT_cross` 南北通透、`VENT_open_window_ratio` 可开启窗占比、`VENT_kitch_bath_exhaust` 厨卫独立对外排风 |
| CIRC | 动线与分区 | 16% | `CIRC_corridor_ratio` 走道占比、`CIRC_wet separation` 干湿分离、`CIRC_public_private` 公私分区、`CIRC_meal_kitchen` 餐厨距离 |
| UTIL | 实用与得房 | 16% | `UTIL_usable_ratio` 得房率、`UTIL_irregular` 异形占比、`UTIL_room_min_size` 最小开间、`UTIL_storage` 收纳墙长度 |
| QUIET | 静谧与干扰 | 10% | `QUIET_road` 临主干道、`QUIET_shaft` 卧室贴电梯井/管井、`QUIET_elevator_ratio` 梯户比 |
| GREEN | 绿色与舒适 | 8% | `GREEN_ceiling` 净高、`GREEN_balcony` 阳台数量与进深、`GREEN_project_rate` 关联绿化率 |
| COST | 经济适配 | 10% | `COST_unit_price_gap` 与楼盘均价差、`COST_total_fit` 与用户预算匹配、`COST_area_waste` 无效面积成本 |

- 每个指标 → 一个 `MetricCalculator`（输入 `HouseTypeDetail` 几何/属性，输出 `double`/`boolean`）；
  指标值经 `eval_rule.tier_json` 落入分档（优 100 / 良 80 / 中 60 / 差 40 或自定义分值），维度分 = Σ(指标得分 × 指标内权重)，总分 = Σ(维度分 × 维度权重)。
- 依据来源必须可引用：住宅相关规范条文编号（如《住宅项目规范》窗地面积比、厨房使用面积下限）、行业设计常识 —— 记入 `evidence.basis`。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-50 | 一键评估：给定 `houseTypeId`（可带 `houseId` 以纳入楼层/朝向/遮挡修正），返回总分、等级（优≥85/良≥75/中≥60/差<60）、维度分、指标明细 | P0 |
| FR-51 | 结果落库为评测记录（含 `detail_json` 快照、`set_version`），同一用户同户型可重复评估并保留历史 | P0 |
| FR-52 | 明细展示：指标名、指标值、命中档位、得分、权重贡献、依据来源、原始数据来源字段 | P0 |
| FR-53 | 人群模板：内置 4 套（刚需三口、改善四房、三代同堂、退休二人、投资客），影响维度权重覆写，不改指标计算 | P1 |
| FR-54 | 分位对比：显示该户型在某指标上"同城 20 个样本"的分位（`percent_rank`） | P1 |
| FR-55 | 规则集版本化：`DRAFT→PUBLISHED→OFFLINE`；PUBLISHED 后只读；同一时刻仅一个 ACTIVE 版本 | P0 |
| FR-56 | 权重之和必须为 1.000（±0.001），否则拒绝保存 | P0 |
| FR-57 | 缺失数据容错：某指标输入为 null 时该指标标记"数据不足"，得分按维度内权重归一化重算，并在明细中显著提示 | P0 |
| FR-58 | 热加载：新发布的规则集无需重启即可用于新评估；历史评测仍按旧版本可复现 | P0 |
| FR-59 | 灵敏度分析：±10% 权重微调后给出总分变化与排名变化（用于 005） | P2 |
| FR-60 | 管理端规则表单：指标下拉（来自注册的 `MetricCalculator`）、运算符、分档表格、依据文本 | P1 |
| FR-61 | 评估耗时 ≤ 200ms（P0 路径 21 指标全算）；结果缓存 10 分钟（同参数 + 同规则版本，键含 `setVersion`） | P0 |

## 5. 验收标准

- **AC-30** Given 窗地比 = 0.16 的客厅，When 评估，Then `LIGHT_wfa` 命中"优"档得 100 分，明细显示 `0.16 ≥ 0.14`、依据"窗地面积比不低于 1/7 相关条文"。
- **AC-31** Given 南北通透 = false 且其余通风指标为 null，When 评估，Then 通风维度只按有效指标归一化，明细标"数据不足 ×2"，且总分仍在 0~100（不因缺数据崩或给 0 分）。
- **AC-32** Given 已发布规则集 v2 且当前 active=v2，When 用户查看 v1 时期的历史评测，Then 显示的规则版本为 v1、明细与当时快照完全一致。
- **AC-33** Given 人群模板"三代同堂"，When 切换评估，Then `UTIL`/`CIRC` 权重按模板覆写，同一户型总分变化幅度可见（≥2 分）且维度分排序可解释。
- **AC-34** Given 管理员把 7 维权重之和保存为 0.95，Then 返回 `40920` 并提示当前和值；补齐 0.05 后成功。
- **AC-35** Given 规则集 v3 发布，When 下一次评估，Then 无需重启即生效（`RuleRepository` 缓存失效），响应 `<setVersion>=v3`。
- **AC-36** Given AI 生成的规则草案（007），When 未经人工确认直接点发布，Then 拒绝（`40303`）并提示"AI 草案需人工审阅"。
- **AC-37** Given 并发 50 用户评估同户型，Then p95 ≤ 200ms（命中缓存 ≤ 50ms）。

## 6. 范围外
用机器学习模型直接回归出总分（不可解释，违反 NFR-11）、真实日照模拟（Ecotect/PV 级）、结构安全计算、
建筑规范自动合规判定（仅做"参考依据"提示，不构成合规结论 —— 界面必须显示该免责文案）。

## 7. 界面与交互要点
`/house-type/:id/evaluate`：顶部等级大字 + 总分环 + 7 维雷达 + 维度卡（可展开明细表）+ 改进建议区 + 「切换人群模板」下拉；
`/admin/rules`：规则集列表（版本、状态、来源）→ 编辑（权重滑块 + 指标分档表格 + 试算按钮）。

## 8. 数据与依赖
输入来自 002（几何/参数）、003（房源修正：楼层、朝向、遮挡、价格）、001（画像：预算、模板）。
被依赖：005（矩阵与结论）、007（AI 解读的事实材料）。
