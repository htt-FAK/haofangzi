# SPEC 007 · AI 能力：规则生成 / 对比解读 / 智能选房顾问 / 3D 代码生成

**版本**: v1.0 | **状态**: Approved | **对应题目**: 创新点 I1 / I2 / I3 / I4
**报告落点**: `docs/03-概要设计` §3.6（AI 网关）、`docs/04-详细设计` §7（提示词与降级流程）、`docs/06` TC-AI-xx

## 1. 目标（WHY）
AI 在本系统不承担"给分"（评分必须可解释，宪法第三条），而是承担三件人做慢、机器做得好的事：
写出/维护成百条评分规则、把评分矩阵翻译成人话、把散乱的偏好收敛成推荐方案，外加把户型参数变成 3D 代码骨架。

## 2. 能力清单

| 编号 | 能力 | 对应创新点 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| I1 | 评估规则草案生成 | AI 生成户型评估规则代码/权重 | 诉求文本（人群、重视维度、预算）+ 基线规则集 | 符合 `scoring-rule.schema.json` 的规则集草案 + 修改说明 + 引用依据 |
| I2 | 对比结论生成 | 自动生成对比报告 | 精简评分矩阵 + 用户画像 | 推荐结论、理由（含 metric 引用）、优缺点、风险、适配人群 |
| I3 | 智能选房顾问 | 结合家庭结构/预算/偏好推荐 | 画像 + 候选户型（≤30）+ 各维度分 | Top-N 排序 + 每条 3 理由 + 2 风险 + 追问问题 |
| I4 | 3D 场景代码生成 | 户型 CAD→3D 初始化代码 | `geometry.schema.json` 数据 | Three.js `buildHouseScene(geom)` 代码串（人工审阅后使用） |
| I5 | 看房要点提示（辅助） | — | 预约 + 该户型低分维度 | 现场核验清单（"实测客厅净宽""检查北向窗可开启"） |

## 5. 验收标准

- **AC-60** Given 诉求"三代同堂 + 重视通风"，When I1，Then 草案 `VENT` 权重 > 基线且 ≤ 0.28（宪法/规则约束），每条改动有 `changeNote`，且草案通过 `scoring-rule.schema.json` 校验。
- **AC-61** Given 未确认的 AI 草案，When 直接发布，Then `40303`。
- **AC-62** Given LLM 返回的 JSON 缺 `tiers` 字段，When 校验失败，Then 自动重试 1 次 → 仍失败 → `MockLlmClient` 结果 + `50310`，接口不报 5xx。
- **AC-63** Given 画像预算 120-160 万、必须 3 房，When I3，Then 返回 3 条结果，全部满足硬性条件且无 `SOLD` 房源，每条含 ≥3 引用 metric 的理由。
- **AC-64** Given AI 结论中某句无指标引用，When 解析，Then 该句被剔除、`hallucinationDropped++` 并写日志（前端不可见无依据文案）。
- **AC-65** Given 60s 内同一用户重复点击顾问，Then 命中缓存（`X-AI-Cache: HIT`），LLM 调用量为 0。
- **AC-66** Given 无外网（`LLM_ENABLED=false`），Then 四项能力全部演示可用（模板结果），并且页面明确标注模板模式。
- **AC-67** Given I4 输出，Then 代码包含 `outline` 墙线、逐房间 `BoxGeometry`、门窗开洞贴图注释，并带 `generatedAt/promptKey` 头注释；不执行、不入库为"可信代码"。

## 6. 范围外
自动发布规则、无监督自我调权、自然语言直接改数据库、以 LLM 输出作为唯一分源、户型图纸 OCR 重建几何、
真实语音/数字人、多轮长会话记忆（追问只做单轮上下文携带）。

## 7. 界面与交互要点
`/ai/advisor`（推荐卡 + 理由 + 风险 + 追问输入 + 免责）、`/admin/rules/ai-draft`（诉求框 + diff 表 + 逐条采纳）、
报告页结论卡角标 `AI/模板`、3D 视图调试抽屉（管理员可见代码）。
