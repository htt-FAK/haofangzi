# SPEC 006 · 预约看房与后台管理

**版本**: v1.0 | **状态**: Approved | **对应题目**: 核心模块 5「预约看房模块」
**报告落点**: `docs/02-需求分析` §2.5、`docs/03-概要设计`（状态转换图）、`docs/04-详细设计` §6、`docs/05` §8

## 1. 目标（WHY）
线上看完要落到线下带看，才算闭环。本域解决"电话/微信登记、时段撞车、临时改约无记录"的老问题：
可视化选时段 → 后台审核排期 → 自动提醒 → 到访与结果留痕，让顾问的排班和客户的时间都不被浪费。

## 4. 验收标准

- **AC-50** Given `14:00-15:00` 容量 6 已满，When 提交，Then `40018` 且返回同日/次日最近 3 个有空位时段。
- **AC-51** Given 已有 `CONFIRMED` 预约，When 同一天再提交，Then `40019` 且提示可改期。
- **AC-52** Given 预约 `COMPLETED`，When 用户点改期，Then `40931 状态不允许`，前端隐藏入口（双重防护）。
- **AC-53** Given 明日 09:00 的 `CONFIRMED` 预约，When 任务运行，Then 生成 1 条客户提醒 + 1 条顾问提醒且 `notified_at` 非空；任务重启后不重复发（幂等）。
- **AC-54** Given 顾问 A，When 查看 `GET /admin/appointments`，Then 仅见 `consultant_id=A`；ADMIN 见全部；A 直接请求他人预约 id → `40302`。
- **AC-55** Given 用户取消，When 后台列表刷新，Then 该时段 `used` 减 1，客户画像保留。
- **AC-56** Given 带 `intentionNo` 的预约成交，When 顾问置 `COMPLETED` 并选"已成交"，Then 关联房源状态可一键置 `SOLD`（同一事务）且留审计。
- **AC-57** Given 导出明日清单，Then 手机号形如 `138****0001`，且无他组顾问的客户。

## 5. 范围外
视频看房、电子签到二维码闸机对接、门禁/人脸识别、客户信用黑名单、真实短信计费通道、售楼部门椅位排程。

## 6. 界面与交互要点
`/appoint/new`（分步：对象 → 时间 → 联系 → 确认）、`/appointments`（我的预约列表 + 详情抽屉 + 改期弹窗）、
`/admin/appointments`（日历视图 + 列表视图切换，状态色标）、`/admin/appointments/slots`（容量矩阵维护）。

## 7. 数据与依赖
依赖 001（登录与角色）、003（意向单转预约）、002（选择看样户型）。写 `appointment`、`sys_message`、`sys_audit_log`；
定时任务与 003 的 `LockExpireJob` 共用调度池（`SchedulerConfig`，`size=2`，避免演示机负载尖峰）。
