# 01 问题定义与可行性

## 1. 问题

售楼处对户型的描述（南北通透、采光好）无法核对。购房者需要在同一套数据上完成：看户型、看可解释评分、对比、锁房意向、预约看房。课程设计范围是演示系统，不接真实网签和支付。

## 2. 可行性

| 方面 | 结论 |
| --- | --- |
| 技术 | Vue 3 + Spring Boot 单体即可覆盖 7 个功能域。评分用 JSON 规则，不依赖规则引擎产品。大模型走硅基流动的 OpenAI 兼容接口，超时回退模板。 |
| 数据 | 种子数据为模拟楼盘（3 个楼盘、20 个户型、600 套房源），无真实个人信息。 |
| 运行 | 学校机房可用 MySQL 8 + JDK 17。无密钥时 `LLM_ENABLED=false`，顾问和对比结论仍能演示。 |
| 进度 | 主路径（筛选、看图、评分、对比、锁房、预约、顾问、管理端规则/销控/用户）已可运行。全景、灵敏度、调用看板留在 `docs/00-ROADMAP.md`。 |

## 3. 约束

分数只由规则引擎计算。模型只写解释文字。密钥只放环境变量，不进仓库。
