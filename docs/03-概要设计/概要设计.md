# 03 概要设计

## 1. 结构

表现层是一个 Vue 应用：购房者页面与 `/admin` 路由分开。应用层是 Spring Boot 单体，按 controller → service → mapper / engine / integration 分层。数据层是 MySQL 8。

```
购房者页面、管理页
        │
   Controller（认证、目录、选房、评估、对比、预约、AI、管理）
        │
   Service ── ScoringEngine（装载规则 → 指标 → 分档 → 汇总）
        │              └── LlmClient（硅基流动，失败则 Mock）
        └── HfMapper → MySQL
```

上层模块与 DFD 加工对应：用户、户型展示、选房、评估、对比、预约、AI、基础数据（管理端）。每个模块下至少有接口、用例服务、持久化三块。评估模块另有指标计算器注册表。

## 2. 关系与物理设计

表结构以 `database/schema.sql` 为准，与 `specs/000-program/data-model.md` 一致。核心关系：

- 楼盘 1—N 楼栋 1—N 房源；户型 1—N 房间、1—N 房源
- 用户 1—N 评测、对比报告、预约、锁房
- 规则集 1—N 维度权重、1—N 指标规则；评测记录冻结 `set_version`

金额、面积用 DECIMAL。业务表含 `id/created_at/updated_at/deleted`。房源锁有唯一索引，保证同一房源同时只有一条有效锁。

## 3. 公共模块

- `ApiResponse`：HTTP 200 + 业务 code
- `GlobalExceptionHandler`：业务异常转统一响应
- `SecurityConfig`：JWT、角色、写接口默认要登录
- 缓存：规则视图与登录失败计数用进程内 Caffeine，不引入 Redis
- 调度：锁超时回收、预约提醒用 `@Scheduled`

## 4. 规则从哪来

`RuleRepository.active()` 先读库中 `active=1` 且已发布的规则集。没有或数据库不可用时，回退 `backend/src/main/resources/rules/default-rules.json`。管理端发布后清缓存，下一次评估用新版本。历史评测仍保存当时的 `setVersion` 和明细快照。
