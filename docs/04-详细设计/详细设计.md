# 04 详细设计

## 1. 打分流程

1. 装载户型、房间、可选的房源/楼栋/楼盘/画像（一次查询组装，不按指标查库）。
2. 取当前规则集。每个 `metricCode` 找到对应 `MetricCalculator`。
3. 计算器给出数值或「数据不足」。`TierMatcher` 按左闭右开命中分档。
4. 维度分 = Σ(指标分 × 维度内权重) / Σ(有效指标权重)。缺指标不把该维打成 0，除非该维全部缺失。
5. 总分 = Σ(维度分 × 维度权重)，等级：优 ≥85，良 ≥75，中 ≥60，否则差。

维度权重：采光 0.22、通风 0.18、动线 0.16、实用 0.16、静谧 0.10、绿色 0.08、经济 0.10。登记表共 25 条规则（规格概述写 21，表内编码已全部实现）。公式见 `specs/004-rule-scoring/plan.md`。

窗地比判定表示例：≥0.14 优，[0.115, 0.14) 良，[0.09, 0.115) 中，&lt;0.09 差。依据为窗地面积比不低于 1/7。

## 2. 锁房判定

| 条件 | 动作 |
| --- | --- |
| 未勾选说明 | 拒绝 |
| 房源不存在 | 拒绝 |
| 他人有效锁未过期 | 冲突 + 备选 |
| 本人有效锁 | 续期（次数和总时长有上限） |
| 状态不是可售 | 拒绝 |
| 条件更新影响行数不是 1 | 回滚并冲突 |

保护顺序：`SELECT … FOR UPDATE`、`WHERE sale_status='AVAILABLE'` 的更新、锁表唯一索引。超时由定时任务释放。状态图：`docs/diagrams/house-state.mmd`。

并发单测没有连接 MySQL，只验证条件更新这一重：20 个线程里只有 1 个把状态从可售改成锁定。

## 3. 预约状态

`docs/diagrams/appointment-state.mmd`。待确认可到已确认或取消；已确认可到到访或取消；到访可到完成。容量按当前待确认+已确认计数，不另存冗余计数。提醒任务用两个时间戳保证不重复发送。

## 4. 大模型

默认 `https://api.siliconflow.cn/v1`，模型 `XingChenAGI/Xing4.0-29B`，超时 20 秒，重试 1 次。先要求 JSON；若接口拒绝 `response_format`，再从正文里截取 JSON。解析失败使用模板，响应码 50310，分数不变。

AI 规则草案的 `source=AI`，未确认不能发布。
